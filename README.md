# إحصاءات تجميع الأراضي

لوحة معلومات تفاعلية لبيانات ملف «تجميع اراضي.xlsx»: العقارات (المحاضر) والإشارات المسجّلة عليها وعقود الشراء وقيم الكشف 16.
البيانات تُستورد من الإكسل إلى قاعدة SQL، والواجهة تقرأ منها عبر API (على نمط «إحصاءات الرواد»: فلاتر متقاطعة بين كل الرسوم، والحالة محفوظة في عنوان الصفحة).

## البيانات لا تُرفع إلى git

ملف الإكسل وملف الـ dump (`deploy/*.sql`) وملفات PDF فيها أسماء ملاك ونزاعات عقارية، لذلك **مستبعدة من المستودع** (`.gitignore`). من يستلم المشروع يحصل عليها مباشرةً ممن يملكها، ثم:

1. ينسخ `server/.env.example` إلى `server/.env` ويضبط بيانات قاعدته.
2. يضع ملف الإكسل في جذر المشروع باسم `تجميع اراضي.xlsx` (أو يغيّر `SOURCE_XLSX` في `.env`).
3. يشغّل `npm run db:import` من `server` (ينشئ القاعدة ويملؤها ويتحقق من المجاميع).

## البنية

| المجلد | المحتوى |
|---|---|
| `server/` | Node + Express + MySQL/MariaDB: مخطط القاعدة (`sql/schema.sql`) والاستيراد (`src/import`) والـ API (`src/app.js`) |
| `frontend/` | React + TypeScript + Vite + Tailwind + ECharts (واجهة عربية RTL، خط Cairo محلي) |
| `تجميع اراضي.xlsx` | المصدر |

## التشغيل (Windows PowerShell)

المتطلبات: Node.js 20+ وخادم MariaDB/MySQL يعمل محليًا (الإعداد الافتراضي `127.0.0.1:3306` بالمستخدم `root` بلا كلمة مرور؛ عدّله في `server/.env`).

أول مرة:

```powershell
cd D:\RealEstate\server
npm install
npm run db:import        # ينشئ قاعدة realestate_insights ويملؤها، ويتحقق أن الإجماليات تطابق الملف

cd D:\RealEstate\frontend
npm install
npm run build
```

كل مرة:

```powershell
cd D:\RealEstate\server
npm start                # http://127.0.0.1:8000  (اللوحة + الـ API معًا)
```

للتطوير (واجهة بتحديث فوري): شغّل `npm start` في `server/` و`npm run dev` في `frontend/` ثم افتح http://127.0.0.1:5174.

عند تعديل ملف الإكسل: أعد `npm run db:import` (يعيد بناء الجداول من الصفر). `npm run db:import:dry` يحلّل الملف ويطبع العدّ والتحذيرات دون لمس القاعدة.

## التحليل المتقدّم

تبويب «التحليل المتقدّم» (`/api/v1/analytics`، الكود في `server/src/analytics.js`) يتبع الفلاتر نفسها، ويضم:

- **القضايا الفعلية**: القضية = نفس رقم الإشارة في نفس المنطقة من نفس الواضع، فتُحسب مرة واحدة مهما تكرر على عقارات (1128 صفًا ≈ 265 قضية).
- **التعرّض للإشارات**: العقارات والمساحة والقيمة لكل نوع إشارة، والنظيفة مقابل الحرجة. الحرجة = تحكيم وأمنية ودولة؛ أما التصفية وفسخ التسجيل فمسجّلتان لمصلحة د. سنكري فلا تُعدّان خطرًا.
- **سعر المتر**: القيمة ÷ «المساحة بحسب الكشف 16» (أساس التقييم نفسه). لا تُحسب قيمة تقديرية للعقارات غير المقيَّمة لأن مساحة الكشف 16 لا تساوي المساحة المملوكة في 30 من 51 عقارًا مقيَّمًا.
- **الفترات الزمنية**: من الشراء إلى الفراغة، ومن الفراغة (أو الحكم) إلى تاريخ الإشارة، بالأيام (وسيط ونطاق وتوزيع). تُحسب فقط حيث التاريخان كاملان.
- **توزيع القيمة**: حصة سنكري وحصة عسلي وبند «غير منسوبة» (قيمة أراضي ذات مشاكل المقيَّمة، وهي لا تدخل في حصة أي منهما).

## قواعد قراءة الملف

- **أول سطر في كل محضر فيه البيانات.** أرقام المحضر (مساحة، حصص، قيمة، كشف 16) تُقرأ من أول صف له؛ والصفوف التالية إشارات وعقود شراء ومالكون. إن بدأت كتلة ثانية بنفس رقم المحضر في نفس المنطقة (مثل 281 في عندان، صف 982) تنضم إشاراتها وعقودها إلى المحضر وتبقى **أرقام المحضر من أول صف له**. فإن كان لسطر الكتلة الثانية رقم كشف 16 مختلف وله قيمة (مثل صف 982: الكشف 74، $65,600) فهو **عملية شراء مستقلة** تُحفظ في جدول `operation_lines` تحت المحضر وتُحتسب قيمتها في الإجمالي، فيطابق مجموع القيمة مجموع الملف (46,680,630.52). وما عدا ذلك من أرقام الكتلة الثانية (رقم كشف 16 نفسه مكررًا مثلًا) لا يُحتسب ويُطرح صراحةً من مجاميع الملف عند التحقق (`مستبعد` في ناتج الاستيراد).
- **الكشف 16 = عملية شراء.** «م ك16» رقم عملية تضم عدة محاضر، وقيمتها ومساحتها تُكتبان مرة واحدة على أول محضر فيها (يتحقق ذلك في كل العمليات المتعددة المحاضر). لذلك تُقاس القيمة لكل عملية لا لكل محضر: 52 عملية (منها الكشف 74 المسجّل تحت المحضر 281) تضم 152 محضرًا، كلها مقيَّمة. المحاضر بلا رقم في الكشف 16 (شقتان ومحضر 1167 وغيرها) تظهر خارج العمليات وقيمتها محسوبة في الإجمالي.
- **الشقق السكنية حالة خاصة:** لا مساحة أرض ولا «وضع عقار»، وحصتها 2400 سهم (بحسب صاحب البيانات، وتُسجَّل في الاستيراد لأنها غير مكتوبة في الملف).
- **التواريخ:** الأعداد في اللوحة بالسنة؛ والتواريخ التفصيلية (يوم/شهر) محفوظة في القاعدة لاستعمالها لاحقًا.
- **نوع الإشارة:** المكتوب في الملف لـ 332 إشارة فقط، والباقي قيد جمع البيانات. التصنيف المستنتج من نص الإشارة يظهر في الرسوم موسومًا «مستنتج».

## جودة البيانات والعمليات ولوحة العقار

- **جودة البيانات** (`/api/v1/quality`، `server/src/quality.js`): كل حقل يُقاس على السجلات التي ينطبق عليها، ويُوسم «قيد جمع البيانات» ما ينتظر استكمال الملف (وضع العقار لمحاضر كفر بسين و160 و165، وسنة بعض الإشارات، ونوع الإشارة). بجانب كل نقص زر «عرض الناقص» برقم الصف في الإكسل، وللقيمة زر «عرض عمليات الشراء».
- **عمليات الشراء** (`/api/v1/operations`، `server/src/operations.js`): عدد العمليات، وعدد المحاضر في كل عملية، وقيمتها الإجمالية ومساحتها وسعر المتر وسنة أول عقد، مع إجمالي. تظهر في تبويب «الشراء والتملّك» وفي «جودة البيانات».
- **لوحة العقار** (`/parcels/:id`): بطاقات مؤشرات، توزيع الأسهم والقيمة، مقارنة بمتوسط المنطقة، بطاقة عملية الشراء ومحاضرها الشقيقة، خط زمني، تحليل الإشارات، وجداول الإشارات والعقود والمالكين.
- أُصلح في الاستيراد: «الحصة السهمية» في الأراضي ذات المشاكل تخص كل مالك مسجّل (`parcel_owners`) لا العقار.

## فلاتر الجداول

فوق كل جدول شريط فلاتر خاص به (يعمل فوق فلاتر اللوحة العامة ولا يغيّر عنوان الصفحة)، فيه مربع بحث نصي يطابق كل كلماته، وقوائم لأعمدة الجدول، وعدّاد نتائج وزر «مسح فلاتر الجدول»:

| الجدول | البحث يشمل | قوائم الفلاتر |
|---|---|---|
| العقارات | المحضر، المنطقة، رقم الكشف 16، الملاحظات | الإشارات، طريقة انتقال الملكية، سنة أول شراء |
| سجل الإشارات | الواضع، على من وُضعت، المحضر، المنطقة، رقم الإشارة | التوقيت، على من وُضعت، مصدر النوع |
| عمليات الشراء (كشف 16) | رقم الكشف، المناطق، الملكية | سنة أول عقد، حجم العملية (إجمالي المعروض يُعاد حسابه) |
| أوسع القضايا | الواضع، المنطقة، رقم الإشارة | النوع |
| الناقص في «جودة البيانات» وسجل إشارات العقار | حسب الأعمدة | التوقيت والنوع (في سجل العقار) |

جدولا العقارات والإشارات يُصفَّيان على الخادم (`server/src/tableFilters.js`، والقيم تُتحقق من قوائم ثابتة قبل SQL) لأنهما مقسّمان إلى صفحات؛ والبقية في المتصفح. القوائم القصيرة (حتى 10 صفوف في الناقص و8 في سجل العقار) بلا شريط لأنها تُقرأ بنظرة واحدة، وجدول «القضايا بحسب النوع» (6 صفوف) وجدول المالكين بلا فلاتر لهذا السبب.

## الوثائق (عقود، بيانات عقارية ومساحية، إشارات، زيارات ميدانية)

بطاقة «وثائق العقار» في لوحة العقار تعرض ملفات المحضر في تبويبات، وفي سجل الإشارات يظهر مشبك بجانب رقم الإشارة التي لها ملف.

- **الفهرسة:** `npm run docs:ingest -- --source "D:\RealEstate\07- ماير" [--dry-run]` من `server`. يقرأ مجلد منطقة واحدة (مجلد لكل محضر، وتحته: إشارات، بيانات عقارية، زيارات ميدانية، عقود شراء، وملفات «بيان مساحي»)، ويحسب SHA-256 لكل ملف، فيُخزَّن كل ملف مرة واحدة مهما تكرر بين المحاضر (ماير: 540 ملفًا، 3.3 GB ← 77 ملفًا فريدًا، 0.26 GB). `--dry-run` يطبع التقرير فقط: الأقسام، المكرر، مجلدات لم تُطابق محضرًا، إشارات في القاعدة بلا ملف، ومحاضر بلا عقد.
- **التخزين:** `DOCS_DIR` (الافتراضي `storage/documents/blobs/<حرفان>/<sha256>`) خارج git. الربط بين الملف والمحضر بـ (المنطقة + رقم المحضر) لا بمعرّف الصف، فلا يضيع عند إعادة `db:import`. جدولا `documents` و`parcel_documents` في `server/sql/documents.sql` وليسا في `schema.sql` عمدًا.
- **الحماية:** الخادم لا يقدّم أي وثيقة إلا إذا ضُبط `BASIC_AUTH_USER` و`BASIC_AUTH_PASSWORD` (فيطلب الموقع كله كلمة مرور)، أو `DOCS_OPEN=1` للتطوير المحلي فقط. وإلا تظهر البطاقة بنص «عرض الوثائق معطّل» ويردّ المسار 403.
- **الملفات على مستوى المنطقة** (مثل «ماير عدة محاضر») تُفهرس ولا تُعرض بعد في بطاقة محضر.

## نموذج البيانات

الملف قائمة مسطّحة: كل عقار (محضر) يبدأ كتلة من الصفوف؛ أول صف يحمل أرقام العقار والصفوف تحته هي الإشارات (وأحيانًا عقود شراء إضافية). في «أراضي ذات مشاكل» تكون الصفوف مالكين مسجّلين.

| الجدول | يمثّل | من أعمدة الملف |
|---|---|---|
| `regions` | المناطق (14) | اسم المنطقة |
| `ownership_groups` | مجموعات الملكية (سنكري 100% / سنكري 75% + عسلي 25% / عسلي 100% / أراضي ذات مشاكل / غير مصنّف) | الملكية |
| `parcels` | العقار: المساحات والأسهم والقيم بالليرة والدولار وطريقة انتقال الملكية | رقم المحضر، م ك16، المساحات، الحصص، القيم، الفراغة/الحكم، الوضع الراهن، ملاحظات |
| `purchases` | عقود الشراء (قد يحمل المحضر أكثر من عقد) | تاريخ الشراء بالعقد، من اشترى |
| `annotations` | الإشارات: التاريخ، الواضع، النوع، على من، التوقيت | رقم/تاريخ الإشارة، واضعها، نوعها، على من وُضعت، قبل/بعد الفراغة |
| `parcel_owners` | المالكون المسجّلون للأراضي ذات المشاكل مع أسهمهم | الوضع الراهن في الصحيفة، الحصة السهمية |
| `annotation_categories` | أنواع الإشارات (6) | — |

الاستيراد يتحقق عند كل تشغيل أن مجاميع القاعدة (القيم بالدولار والليرة، المساحات، عدد الإشارات وعقود الشراء) تساوي مجاميع الملف حرفيًا، ويفشل إن اختلفت.

## قرارات تحليل الملف (تستحق المراجعة)

- **نوع الإشارة**: الملف يملأ «نوع الإشارة» لنحو 30% من الإشارات فقط (تحكيم، أمني، تصفية شركة، دولة). الباقي صُنّف من نص «اسم واضع الإشارة»: «فسخ…» ← فسخ تسجيل، «استملاك/بلدية/مجلس…» ← دولة، وأسماء الأفراد ← «دعوى / قيد أفراد» (68% من الإشارات). عمود `category_source` يبيّن أيهما من الملف وأيهما مستنتج، والصفحة تعرض نسبة المستنتج في «جودة البيانات». القواعد في `server/src/import/parse.js`.
- **التواريخ**: الملف يخلط أرقام إكسل وسنة فقط ونصوصًا مثل `13-1-2008`. تُقرأ كلها، والإشارات المعروفة بالسنة فقط (478 إشارة؛ و7 أخرى بلا أي تاريخ) تُحفظ بسنتها دون يوم، وتدخل رسوم السنوات لا الأشهر. التواريخ النصية تُقرأ يوم-شهر-سنة.
- **المساحة المملوكة** = «الملكية من مساحة المحضر»، وهي غير مسجّلة لمعظم الأراضي ذات المشاكل، فتظهر «—» لا صفرًا.
- **القيمة بحسب الكشف 16** مسجّلة لـ 55 عقارًا فقط من 167؛ مجموع 46.68 مليون دولار يخص هذه العقارات وحدها.
- **الأسهم**: العقار الواحد 2400 سهم.
- صفوف الإشارات التي تحمل أسهمًا إضافية (حصة سنكري/عسلي بجانب الإشارة) تُحفظ في `row_sankari_shares` و`row_asali_shares` في جدول الإشارات.
